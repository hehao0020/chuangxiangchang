# 创想场 PRD v0.2

> 项目代号，名称待定。面向中国用户的 AI 时代综合创作与体验社区。
>
> 文档日期：2026-11-16｜状态：产品评审稿｜范围：完整愿景与首版 MVP
>
> v0.2 修订：游戏、工具及其他创作从首版即可共存；首页默认跨分类综合推荐；分类用于组织、筛选与理解兴趣，不要求用户先选分类。内容类别与技术运行能力分开定义。
>
> 本文基于创始人提出的机会判断形成，尚未完成用户访谈或市场规模验证。文中的规模、指标、限制和阶段安排均为首轮产品提案，不代表既有数据、已获资源或上线承诺。

## 1. 产品结论

**让每个人的想法成为可以被直接体验、评价和继续创作的作品。**

创想场承接创作者使用不同 AI 或开发工具制作的游戏、工具、互动故事、设计、学习作品、创意实验和其他创作。创作者发布作品，用户在统一首页发现不同类型的内容，直接体验、评论、收藏和关注更新，形成围绕创意与作品的社区。

**首页是综合推荐信息流。游戏、工具及其他创作可以出现在同一条信息流里；分类是辅助发现的方式。** 用户无需先回答“今天想玩游戏还是找工具”才能进入平台。

首版优先解决“已经做出来，怎样让别人方便地体验并给予反馈”。先建立发布、发现、体验、反馈、更新的闭环，再扩展站内 AI 生成和授权改编。

产品定位是大众综合创作与体验社区。作者可以具备编程能力，也可以通过 AI 或可视化工具创作；不以职业、开发经验或使用某一家模型作为入场条件。

首版通过通用网页作品容器支持多种创作。同一个容器可以承载游戏、计算工具、3D 展示或互动教程，不为每个分类重复建设一套社区和发布系统。新类型满足运行与审核条件即可进入平台，不因不属于预设三类而拒收。

## 2. 背景与机会假设

### 2.1 已观察到的现象

- 创始人已观察到 AI 生成网页游戏、工具等作品，以及通过视频、图文展示作品的行为。
- 浏览器可以承载可交互的网页作品，使一部分作品无需独立安装包即可体验。
- 现有内容平台已有小程序等体验入口，同时存在各自的接入、运营和分发规则。

这些现象支持进一步验证需求，尚不足以证明一个独立平台必然成立。

### 2.2 本产品要验证的假设

| 编号 | 假设 | 验证方式 |
| --- | --- | --- |
| H1 | 已有创作者愿意多发布到一个能带来真实体验和反馈的平台 | 邀请已有作品的作者，记录完成发布率与再次更新率 |
| H2 | 用户愿意消费陌生人制作的互动作品 | 观察有效体验、单次访问体验作品数与主动复访 |
| H3 | 直接体验比单纯观看介绍更容易产生有用反馈 | 在同一作品上观察进入体验后的反馈内容，并做访谈 |
| H4 | 体验和反馈能够推动作者更新作品 | 追踪反馈、作者回复和后续版本之间的关联 |
| H5 | 国内可访问、中文社区和较少的发布步骤能吸引第一批用户 | 访谈流失作者，对比原有发布过程与本平台过程 |
| H6 | 不同类型的创作可以在综合推荐流中共同带来发现价值 | 观察跨类型体验、主动筛选、隐藏反馈及复访，排查是否存在用户不需要的强制混排 |

### 2.3 不作为立项依据的判断

- 不以“旧平台有意压制全民创作”作为已证实事实。
- 不以“现有平台只能付费推广”作为已证实事实。
- 不假设程序员与普通创作者天然对立。
- 不假设作品文件小，就一定加载快、运行流畅或制作便宜。
- 不假设使用网页形式就可以省略运营所需的审核、资质或其他要求。

## 3. 目标用户与核心任务

| 用户 | 典型情境 | 要完成的任务 | 当前需要验证的困难 |
| --- | --- | --- | --- |
| 已有作品的个人创作者 | 用 AI 或其他工具做出游戏、工具、设计等作品 | 快速发布，获得第一批体验者与具体反馈 | 发布步骤多、缺少用户、展示和体验分离 |
| 普通体验者 | 想找新鲜、短时、有趣或有用的内容 | 快速判断并进入体验，收藏值得回来的作品 | 找不到入口、不愿下载、不确定能否运行 |
| 参与者 | 玩过作品后产生新想法 | 提建议、报告问题、关注作者后续更新 | 反馈分散，作者是否收到和处理不清楚 |
| 平台编辑与审核员 | 每天有新作品和新版本提交 | 判断是否可运行、适合公开展示，并处理问题 | 可执行内容的风险高于静态图文 |

首批创作者优先邀请已经拥有可运行作品的人。首批体验者应同时包含创作者圈外的普通用户，避免把同行互评误认为大众需求。

## 4. 产品边界

### 4.1 长期愿景

建设多类型创作共存的平台：首页综合推荐，用户可主动进入分类、搜索或关注流。作品可以被发现、使用、讨论、更新，并在作者授权下改编。游戏、工具、设计、故事、学习与其他创意均属于产品内容范围。成熟后再评估创作工具、商业化和更复杂的运行能力。

必须分别管理两个维度：**内容类别**回答“作品有什么用途或体验”，**技术能力**回答“平台当前能否承载它”。例如一个不需要联网的学习模拟器可以首版发布；需要自定义后端的游戏要等待相应运行能力。不能把技术能力暂未开放写成某个内容分类不能进入平台。

### 4.2 P0：本次 MVP 必须具备

- 移动浏览器优先的体验端，以及适合电脑操作的上传与管理工作台。
- 接收单 HTML 文件或自包含网页 ZIP 包。
- 支持可扩展的作品分类，初始包含游戏、工具、故事与互动叙事、设计与视觉、学习与模拟、创意实验、其他；分类并非封闭清单。
- 作品审核、隔离运行、详情页与独立分享地址。
- 首页综合推荐信息流、可选分类筛选、标题及标签搜索；不同分类在同一首页中展示。
- 评论、问题反馈、作者回复、点赞、收藏、关注作者。
- 作者数据面板、版本更新、下架与回滚能力。
- 举报、审核后台、作品紧急停用能力与基础数据埋点。

所有分类共用作品、作者、版本、评论、收藏、审核与推荐体系。首版可以承载无需外部账号、外部服务或敏感权限的自包含网页作品，例如游戏、计算器、互动故事、3D 空间设计、数学模拟和声音实验。限制针对运行能力，对所有分类一致适用；操作提示和主按钮按作品用途呈现。

### 4.3 P1：在 P0 需求成立后评估

- 作者授权的站内改编、来源关系和改编作品页。
- “我有一个想法”的需求帖，以及作者认领、实现后的关联。
- 可复用模板、专题挑战、作品合集。
- 站内消息与更细的体验行为分析。
- 工具专用的搜索、复用与收藏组织方式。

分类扩展属于 P0 的内容管理能力，不需要等待 P1。后续阶段扩展的是更复杂的运行、创作和协作能力。

### 4.4 P2：另行立项

- 站内 AI 创作和对话修改、多模型接入。
- 在线协作编辑、作品后端托管、多人实时联机。
- 作者收益、付费作品、打赏、广告与交易结算。
- 原生 App、小程序渠道适配与开放接口。

P0 不支持任意安装包、任意外链嵌入、外部登录、支付、实时模型调用、自定义服务器和作品读取平台用户身份。首版不开放私信，不设置粉丝付费投流。

## 5. 成功标准与指标口径

### 5.1 首版核心指标

**每周有效体验用户数：一周内至少完成一次有效体验的去重用户数。**

它衡量实际使用，而非上传数量、视频播放或作品页面曝光。必须同时看体验者留存与作者更新，不能只靠拉新放大指标。

### 5.2 事件口径

| 名称 | 定义 |
| --- | --- |
| 卡片曝光 | 卡片至少 50% 面积进入可视区并连续停留 1 秒 |
| 进入体验 | 用户主动点击作品的体验按钮，例如“开始游玩”“立即使用”“打开作品”，平台开始加载作品 |
| 运行容器就绪 | 平台已建立运行容器；不等同于游戏画面或功能已经可用 |
| 作品就绪 | 作品主动上报就绪，或在编辑器人工验收中确认就绪；两种来源分别记录 |
| 有效体验 | 进入体验后，在前台累计停留至少 30 秒且发生可观测的作品交互；或完成审核认可的短任务完成事件并发生作品交互；点击开始按钮本身不计 |
| 有用反馈 | 指向具体操作、问题、玩法或改进建议的反馈，由抽样人工标注；不以字数自动判断 |
| D7 留存 | 首次有效体验后第 7 个自然日再次有效体验的用户占比；按北京时间计算 |
| 作者更新率 | 有作品公开满 14 天的首发作者中，首发后 14 天内至少发布一次新公开版本的作者占比 |

作品自行上报的事件均属于不可信输入。有效体验结合平台可观测的前台停留、体验区域焦点、经审核的交互事件及异常过滤计算。跨来源隔离意味着平台不能直接读取作品内全部输入，需在工程评审中明确受限制的观测方案，并验证不能采集输入正文。未获得可靠交互数据的会话仅计入进入体验与停留，不伪称有效体验；数据面板同时展示观测覆盖率。通用统计无法可靠判断任意作品是否完成目标，因此任务完成口径必须单独审核，且报告时与 30 秒口径分开披露。

30 秒口径不是所有类别的唯一成功标准。工具的任务完成、设计作品的查看/调整、学习作品的练习完成等事件可经审核纳入第二种口径。未接入可靠完成事件时，不能将短时使用直接标为失败；应同时展示体验进入、收藏和复用指标。平台核心指标跨类汇总，分析和排序须保留分类口径。

### 5.3 首轮验证目标

以下为待校准的实验目标，不是行业基准。未达到目标时应追查原因，不用单一数字决定项目生死。

| 维度 | 初始目标 |
| --- | --- |
| 内容准备 | 20—30 位作者，约 60 个经审核可体验作品，覆盖至少游戏、工具和两种其他创作类别；数量不代表必须平均配额 |
| 体验样本 | 至少 300 位真实体验者，其中至少一半来自创作者圈外 |
| 作者发布 | 对准备好合格文件并进入上传流程的作者，最终成功公开比例 ≥70% |
| 首次体验 | 有曝光的真实用户中，至少进入一次体验的比例 ≥25% |
| 体验转化 | 进入体验的用户中，至少有效体验一次的比例 ≥50% |
| 消费深度 | 有效体验用户中，当次访问有效体验至少 2 个不同作品的比例 ≥25% |
| 体验者留存 | D7 留存目标 ≥15%；成熟样本少于 100 人时仅做观察，不做稳定结论 |
| 作者持续性 | 作者 14 天更新率目标 ≥25% |
| 反馈质量 | 至少 30% 的作品在公开 7 天内收到一条有用反馈 |
| 多类型发现 | 记录各类曝光与有效体验分布、跨类型体验人数、不感兴趣率和次周复用；先取得基线，不为了达标强迫用户跨类消费 |

所有比例同时展示分子、分母、时间窗；内部账号、明显机器人、异常自刷分开统计。作者自己体验自己的作品不计入公众体验指标。

## 6. 信息架构

### 6.1 体验端

- **首页**：默认“推荐”综合流，辅助入口为关注、分类、新作与搜索。分类可直接切换，但不会在进入时强制弹出选择。
- **收藏**：收藏的作品、最近体验、关注作者的新版本。
- **我的**：账号、个人主页、我的作品、反馈记录、发布入口。

每个作品拥有独立详情地址。未登录用户可查看、体验及提交基础举报；点赞、收藏、关注和评论需登录。登录完成后回到原操作位置。

### 6.1.1 首页组织

- 顶部展示搜索入口，以及“推荐 / 关注 / 分类”切换；默认进入推荐。
- 推荐中混排不同类别的作品，以兴趣与质量决定顺序，不按固定类别轮播，不要求每屏凑齐全部类别。
- 卡片统一展示封面或静音预览、标题、一句话体验说明、作者、类别与设备支持；可直接点击主按钮进入体验，点击标题进入详情。
- 主按钮按体验方式显示，如“开始游玩”“立即使用”“进入故事”“查看设计”；未知新类别回退到“打开作品”。
- 卡片支持收藏、不感兴趣和举报；不感兴趣可选择减少该作品、同类内容或该作者。单次反馈不是永久封禁某类兴趣。
- 浏览时不自动运行所有作品；作品仅在主动进入后启动。退出体验返回原推荐位置。
- 关注流展示关注作者的公开作品与合并后的版本更新，跨分类共存；分类页提供主动筛选，搜索结果默认可跨类查找。

### 6.1.2 可扩展分类模型

| 初始分类 | 示例 | 进入后的主要动作 |
| --- | --- | --- |
| 游戏 | 射击、解谜、休闲、沙盒 | 玩、挑战、再次体验 |
| 工具 | 计算、文本处理、配色辅助 | 输入、处理、查看结果、收藏复用 |
| 故事与互动叙事 | 选择剧情、互动漫画、分支故事 | 阅读、选择、推进情节 |
| 设计与视觉 | 3D 空间、交互海报、创意网页 | 查看、旋转、调整、探索 |
| 学习与模拟 | 物理实验、数学可视化、互动练习 | 调参、模拟、练习、理解 |
| 创意实验 | 声音实验、生成艺术、趣味交互 | 探索、生成、体验 |
| 其他 | 尚未形成独立分类的合格作品 | 使用通用作品容器打开 |

分类和体验方式分别存储。每个作品选择一个主分类，可补充最多两个关联分类及兴趣标签；同一作品不因归属多个分类而在同一次推荐中重复出现。跨界作品无需拆成多个投稿。

运营后台可新增、改名、排序、合并分类，不要求客户端发版。合并时保留作品、收藏、分享地址和历史统计的可追溯关系。“其他”作品有同等审核和探索机会，不能因未知分类被自动排除。已有作品归类调整不会自动改变其运行权限。

### 6.2 创作者工作台

作品列表 → 新建/编辑 → 上传检查 → 预览 → 提交审核 → 公开 → 数据与反馈 → 更新版本。

### 6.3 运营后台

作品及版本审核、举报处理、精选配置、标签维护、作者管理、运行异常与操作记录。

## 7. 核心用户流程

### 7.1 用户发现并体验

1. 打开首页，直接看到跨类型推荐作品的封面、名称、一句话介绍、作者、分类及设备支持，无需先选分类。
2. 点击卡片主按钮可直接进入体验；点击标题进入详情，通过分享链接进入时直接到详情。
3. 点击体验按钮后，出现加载状态、设备提示和退出入口；按钮文案随作品体验方式变化。
4. 进入独立体验区域，按作品需要切换横屏或全屏。
5. 退出后回到原卡片位置，可点赞、收藏、评论或反馈问题。
6. 用户主动进入下一个作品。首版不强制跳转或自动运行下一项。

### 7.2 作者首次发布

1. 登录并完成平台要求的作者信息。
2. 上传 HTML 或 ZIP，系统进行结构、体积、依赖与风险检查。
3. 填写作品资料、设备支持、操作方式、来源与 AI 使用声明。
4. 在隔离预览环境检查作品，查看运行日志和失败原因。
5. 完成发布前自查，提交审核。
6. 审核通过后获得公开地址；不通过时看到具体原因和修复方向。
7. 查看真实体验和反馈，再提交下一版本。

### 7.3 反馈促进更新

用户提交问题/建议 → 作者在工作台查看 → 作者回复或标记处理状态 → 新版本通过审核 → 作者可将更新与对应反馈关联 → 原反馈用户在站内看到处理进展。

站外通知不属于 P0；不将每次评论或版本更新都推送给全部关注者。

## 8. P0 功能需求

| ID | 功能 | 必须具备的行为 | 验收要点 |
| --- | --- | --- | --- |
| F01 | 首页综合推荐 | 默认混排多类作品；提供关注、分类、新作入口及不感兴趣反馈；恢复浏览位置 | 未选分类也能看到推荐；多类样本可进入同一流；返回保留位置；尊重主动筛选和负反馈 |
| F02 | 搜索 | 按标题、作者名、标签查找公开作品 | 不展示草稿、未过审或已下架内容；无结果有明确提示 |
| F03 | 作品详情 | 展示作品介绍、作者、版本、设备、操作说明、来源及互动 | 分享链接直接进入同一作品；不支持设备有说明 |
| F04 | 作品运行 | 主动加载、隔离运行、横屏/全屏、平台退出入口 | 加载失败能返回和重试；不要求先登录才能体验 |
| F05 | 收藏与关注 | 收藏作品，关注作者，查看关注更新 | 重复操作不产生重复记录；取消后状态一致 |
| F06 | 评论与反馈 | 普通评论、问题、建议三种类型；作者回复与处理标记 | 文本转义；具备频率限制、举报与管理能力 |
| F07 | 上传与预览 | HTML/ZIP 检查、资料编辑、隔离预览、提交审核 | 失败给出可执行原因；上传不等于公开 |
| F08 | 版本管理 | 创建新版本、审核、发布、回滚、下架 | 新版本待审时旧版可继续体验；审核通过才能切换 |
| F09 | 作者面板 | 展示曝光、体验、有效体验、收藏、反馈及设备分布 | 口径可查看；剔除作者自刷；异常数据可标记 |
| F10 | 举报审核 | 举报入口、审核队列、暂停访问、处理结果 | 紧急停用覆盖详情、体验地址、分享入口和运行资源 |
| F11 | 个人主页 | 展示作者资料和公开作品 | 草稿和待审版本对其他用户不可见 |
| F12 | 站内通知 | 审核结果、作者收到的反馈、用户反馈处理结果 | 未读可清除；同类高频通知合并 |
| F13 | 可扩展分类 | 后台管理分类；支持跨界作品、其他分类与通用容器 | 新增分类无需客户端发版；合格其他类作品可发布、推荐、搜索；归类不改变权限 |

## 9. 作品发布规范

### 9.1 作品资料

| 字段 | 要求 |
| --- | --- |
| 名称 | 2—30 个字；避免误导性官方身份或性能承诺 |
| 一句话介绍 | 最多 60 个字，说明用户能做什么 |
| 详细介绍 | 最多 2,000 个字；包含操作方式和已知限制 |
| 封面 | 至少 1 张；以作品真实画面为主，必要时可使用说明图 |
| 分类 | 从后台维护的分类中选择一个主分类，可选最多两个关联分类；允许“其他”，可申请新分类 |
| 体验方式 | 游玩、使用、阅读、查看、模拟或通用打开；用于按钮与操作说明，不决定能否发布 |
| 标签 | 1—5 个，优先选择平台已有标签 |
| 支持设备 | 手机、电脑，可多选；明确触屏/键鼠、横屏/竖屏 |
| 预计体验时长 | 1 分钟内、1—5 分钟、5 分钟以上，供用户参考 |
| AI 使用声明 | 未使用/辅助创作/主要由 AI 生成；可补充使用环节 |
| 来源与权利声明 | 原创/基于获授权内容；后者填写来源与授权依据 |
| 更新说明 | 新版本必填，首次发布可省略 |

AI 使用信息由作者申报，平台不把申报结果包装成模型或原创性认证。对具体模型不设入驻限制。

### 9.2 首版包格式

- 支持 UTF-8 的单 HTML 文件，或根目录包含 index.html 的 ZIP 包。
- JS、CSS、模型、图片和音频依赖应包含在包内；不依赖外部 CDN、模型 API 或自定义后端。
- 初始限制：上传包不超过 20MB，ZIP 解压后不超过 50MB，文件数不超过 500。以上为容量提案，内测按真实作品调整。
- 解压过程必须限制路径、层级和总体积，拒绝可执行安装文件及不允许的文件类型。
- 不接受以网页包形式包装的外部网站跳转器。
- 上传后提供体积、文件结构和外部依赖检查结果；不符合时保留草稿供修复。

### 9.3 运行能力边界

- 可以使用浏览器图形与音频能力；音频由用户操作触发。
- 不允许作品访问平台账号、登录凭证或其他作品数据。
- 默认禁止外部联网、弹窗、顶层导航、摄像头、麦克风、定位、剪贴板和任意下载。
- 首版不保证跨设备存档，不把本地存储作为作品必须依赖的能力；平台收藏与体验记录单独保存。
- 不支持设备必须在开始前提示，不能让用户经历长时间加载后才知道不能操作。
- 作品客户端代码会发送到用户设备，不能承诺源代码绝对保密。来源与改编权利通过声明、授权和治理机制管理。

## 10. 推荐与新作者曝光

### 10.1 首版分发原则

首页默认跨分类综合推荐。首版采用人工选品、基础兴趣信号和简单规则排序；不要求先建成复杂算法，但多类型混排、反馈和分类扩展必须在 P0 可用。

- 默认从当前设备可体验的全部分类中召回候选作品；只有用户主动筛选时才限制分类范围。未选择兴趣的用户直接获得跨类型初始推荐。
- 分别保留“精选”“新作”入口，精选明确标记人工推荐。
- 内测为合格新作安排初始体验机会，目标为公开 7 天内获得 30 次合格卡片曝光；供给超过流量时显示排队状态，不承诺无限免费流量。
- 不按 AI 模型名称、粉丝数或上传数量直接决定优先级。
- 优先观察运行成功、有效体验、再次体验/收藏和负反馈，原始点击量只作为辅助。

### 10.2 综合推荐流程

1. 资格检查：作品已公开、适合展示、设备兼容、无当前用户屏蔽或重复曝光限制。
2. 多来源召回：人工精选、新作品探索、历史兴趣相近作品、适量尚未熟悉的类别。
3. 类型内评估：依据该类作品的真实使用信号评估表现。游戏看有效游玩、复玩；工具看完成、收藏、跨日复用；设计、故事、模拟按其体验目标评估。
4. 综合排序：结合基础兴趣匹配、类型内表现、新鲜度和探索机会进入同一列表。P0 可通过精选等级、兴趣标签交集和类型内质量档位排序，所有新类别有默认档位与探索入口，不要求先训练模型。
5. 列表调整：减少同作品重复、同作者连续刷屏和高度相似内容；不把多类型共存写成固定类别配额。用户偏好工具时允许出现更多工具。
6. 反馈更新：收藏、关注、再次体验作为正向信号；不感兴趣、确认的质量问题作为负向信号。保留探索空间，避免一次点击就把用户锁进单一类别。

新用户不依赖强制兴趣问卷；兴趣选择可自愿跳过。首版目标是让综合推荐可运行、可解释、可观察，后续再根据样本调整权重。

### 10.3 降低分发偏差

- 所有类别在同一推荐流中展示，但质量评估保留分类口径，不用总停留时长给所有作品统一排名。
- 工具完成任务快可能是优点，不以“停留短”直接降权；故事、设计与学习作品也有对应的完成和互动信号。
- 新作先探索、小样本时保留机会；同一账号的重复体验不重复增加探索完成量。
- 封面和介绍与实际体验明显不符时要求整改；有举报不直接等同违规。
- P0 不销售推荐位。未来如引入商业推荐，应明确标识，并单独评审对自然分发的影响。

## 11. 社区互动与授权改编

### 11.1 P0 互动

评论最多 1,000 字，首版纯文本。问题反馈可附类型、复现步骤、期望结果；设备、版本、浏览器等最小必要信息经说明后自动附带，不采集用户输入的业务内容。

作者可将反馈标为“已收到、计划处理、已修复、暂不处理”，最后一种可以说明原因。社区评论与结构化反馈均关联用户体验时的作品版本，避免修复后仍把旧问题当作当前故障。

作者可管理自己的回复，不能私自删除其他人的正常批评；违规内容通过平台治理处理。作品作者账号在评论区带明确身份标记。

### 11.2 P1 改编原则

不因作品公开就默认允许他人站内改编。作者可选择禁止改编或按明确条款授权改编；授权作品保留原作、改编者和版本关系。

具体许可证、可下载范围、商业使用和撤回授权对既有改编的影响，需要在 P1 启动前完成独立条款设计。平台不能只展示“支持原创”的文案而不明确实际权利。

### 11.3 想法如何进入社区

P0 在作品反馈中收集“我希望增加什么”。P1 再开放独立想法帖，关联认领者和实现作品。不把未实现想法与可体验作品混排为同一种内容，避免用户点开后反复落空。

## 12. 作品与版本状态

| 状态 | 可见性 | 后续操作 |
| --- | --- | --- |
| 草稿 | 作者可见 | 编辑、预览、提交、删除草稿 |
| 检查中 | 作者可见 | 等待结果，失败后修复 |
| 待审核 | 作者及审核员可见 | 审核通过、驳回或作者撤回 |
| 已驳回 | 作者可见具体原因 | 修改后重新提交 |
| 已公开 | 所有人可访问 | 提交新版本、主动下架或平台处置 |
| 作者下架 | 公众不能运行，保留不可用说明 | 作者申请重新公开，需复核 |
| 平台暂停 | 公众不能运行 | 复核、申诉、恢复或确认移除 |
| 已移除 | 不可运行 | 按平台规则保留必要记录与申诉入口 |

作品资料与包文件组成一个审核快照。新版本或影响安全与权利判断的资料修改必须复审。公开版本不可被作者静默替换文件。

发布切换和回滚均为原子操作：一次访问只能使用同一完整版本。只允许回滚到仍然合格的历史版本，不能回滚到已因风险撤销的版本。

作品下架不自动删除已有反馈和必要审计记录；公众页面展示范围按下架原因和隐私要求处理。

## 13. 加载、异常和无障碍体验

| 场景 | 用户看到什么 | 必须提供的操作 |
| --- | --- | --- |
| 加载较慢 | 3 秒后出现明确加载说明；15 秒后出现“加载时间较长” | 返回、重试、问题反馈；不能伪造进度百分比 |
| 作品异常或黑屏 | 平台提示可能未正常运行 | 退出、重试、反馈；保留作品版本与必要错误信息 |
| 网络断开 | 平台提示网络状态；区分包下载失败与作品运行问题 | 恢复后由用户重试，避免重复提交操作 |
| 手机仅支持电脑 | 开始前明确说明设备不支持 | 收藏、分享、返回其他作品 |
| 不支持图形能力 | 说明当前设备不能运行该作品 | 返回与查看兼容作品 |
| 没有搜索结果 | 保留用户搜索词 | 清空筛选、查看其他类型 |
| 作品被下架 | 说明当前不可体验，不自动跳转到无关内容 | 返回、联系平台或查看作者其他公开作品 |
| 评论失败 | 保留输入文本 | 重试，显示是否需要登录 |
| 登录中断 | 不丢失原作品位置和待执行动作 | 返回体验或重新登录 |

平台外层导航、按钮、评论区支持键盘操作、清晰焦点与基础读屏。作品自身的无障碍能力单独标注，不将外层可访问性等同于作品完全可访问。

平台退出按钮不由作品绘制，始终可触达。全屏与指针锁定保留系统退出方式。P0 对高负载作品不承诺无条件强制中断，隔离运行、停止加载和异常退出能力须经过设备验证。

## 14. 安全、审核与运营责任

### 14.1 运行隔离

作品运行环境与主站账号环境分离，采用独立来源隔离及受限制的运行容器。明确限制网络和浏览器权限；不能仅靠文件扫描判断安全。

作品间和作品与主站之间不能共享身份凭证。作品发给平台的消息只接受限定格式，并校验发送来源、版本和权限；不能允许作品任意触发主站动作。

### 14.2 审核流程

自动检查 → 人工预览 → 核对来源与声明 → 判断是否可公开 → 通过/具体驳回。

内测目标为提交后 2 个工作日内给出首次处理结果。审核积压时应向作者展示状态；该目标不作为无条件服务承诺。

每个新版本都要检查运行与权限变化。人工预览至少覆盖作者声明的主要设备类型。提交文件检查、实际运行观察和来源核对分别记录，避免用“机器已通过”代替全部审核。

### 14.3 举报与紧急处理

举报类型：无法运行、误导内容、侵权、危险行为、骚扰或其他。举报数量触发复核优先级，不直接依据数量自动认定违规。

确认存在紧急风险时，平台可以暂停作品、作者继续发布能力及相关资源访问。运营端需具备停用开关和处理日志；异常监控不能只修改列表展示而保留可直接访问的作品包。

### 14.4 上线前必须确定的事项

根据实际运营主体、作品类型、运行方式、用户年龄与商业模式，核实上线所需的资质、备案、内容管理及未成年人相关要求。具体结论须由适用规则核实和专业评估形成，本 PRD 不做豁免承诺。

审批和安全能力未具备时先开展受控测试，不通过改名“作品”或改用 HTML 回避应适用的要求。

## 15. 技术与性能验收目标

以下为待工程验证的目标；开发前应确定具体测试设备、网络限速、浏览器版本及作品样本。

| 项目 | 初始验收目标 |
| --- | --- |
| 主站体验 | 普通手机与电脑浏览器可完成发现、登录、收藏和反馈；至少覆盖 iOS Safari、Android Chrome、桌面 Chrome/Edge 的约定版本 |
| 首屏 | 在约定中端手机、10Mbps 下行及 80ms 往返延迟条件下，首页主要内容 P75 在 2.5 秒内可见 |
| 作品加载 | 在同一条件下，初始下载不超过 5MB 的指定样本，点击开始到可交互 P75 ≤5 秒；大包单独报告 |
| 外层退出 | 约定样本和设备下，正常运行时外层退出操作 P95 在 1 秒内响应 |
| 运行质量 | 经人工检查的测试样本，进入后可完成首个核心操作的比例 ≥95%；不以 iframe 加载完成冒充可用 |
| 版本一致性 | 更新期间没有新旧资源混用；失败可恢复上一合格版本 |
| 紧急停用 | 在约定测试环境中，操作后 60 秒内阻止新会话访问主站及直接资源入口；已下载到本地的副本不在远程撤回承诺内 |

若运行目标无法实现，优先限制支持的作品能力与设备范围，再决定是否公开上线。不得用放宽权限绕过隔离问题。

## 16. 数据、隐私与事件清单

### 16.1 最小事件集

page_view、work_impression、work_detail_view、experience_start、container_ready、work_ready、first_interaction、experience_end、experience_error、like、favorite、follow、feedback_submit、author_reply、upload_start、upload_result、review_submit、review_result、version_publish、report_submit、work_suspend、category_select、feed_switch、not_interested。

与作品相关的事件至少带 work_id、version_id、主分类、体验方式、推荐来源、入口、设备类别、时间及必要的会话标识。作者自访、内部测试和异常流量带单独标记。not_interested 记录用户主动选择的减少范围，不记录输入正文。

### 16.2 数据边界

- 不默认录屏、记录完整键盘输入、读取作品中用户填写的文本。
- 游客识别采用最小必要方案，不使用侵入式设备指纹补齐所有跨设备关系。
- 作者可看自己作品的汇总数据，不获得体验者的联系方式或完整身份。
- 运行日志只采集排障必要内容，注意日志中可能混入用户输入或秘密信息，需限制、脱敏和设置保留周期。
- 上线前确定隐私告知、账号注销、公开内容处理及日志保留策略。

## 17. 冷启动与运营方案

### 17.1 先准备内容

邀请已有作品的作者，帮助将作品整理为合格包。收集每一步卡点，判断究竟是格式转换、权限、审核、缺少玩家还是反馈不足。

首批约 60 个作品兼顾游戏、工具及其他创作，以“用户能明确获得乐趣、用途、审美或理解”为标准。简单工具可几秒完成任务，设计或学习作品可以需要更长探索；不强求相同时长。内容准备保持多样性，不将所有类别锁定在平均配额。首页不以模型名称和技术炫技作为唯一卖点。

### 17.2 再引入体验者

作者分享独立作品地址；用户先进入作品，再选择是否进入社区。组织小范围主题试玩，明确邀请体验者提出具体反馈，不要求好评。

如通过现有内容平台展示作品，遵守相应规则，不将绕过站外限制作为获客前提。测试直接链接、搜索品牌名、朋友分享等不同来源的实际转化。

### 17.3 每周复盘

- 哪些作品被点开、哪些完成了体验，两者为什么不同？
- 用户离开是加载、操作、内容还是缺乏后续兴趣造成的？
- 新作者有没有收到真实玩家反馈，是否因此更新？
- 圈外用户会不会主动回来？
- 单个作品体验、审核和运营的成本是多少？
- 不同类别能否在首页被发现？用户是否自主进入分类？混排是否改善发现，还是出现不相关内容干扰？

活动可产生初始流量，最终判断应单独看非活动时段与非奖励用户行为。

## 18. 商业模式与成本边界

P0 以验证真实体验和持续创作为目标，不上线打赏、广告、付费作品或付费推荐。

后续优先评估有明确交付价值的服务，例如更大容量、运行诊断、团队管理和高级分析。交易分成、商业发行或 AI 创作额度另行评审，不把免费自然流量作为永远无限的承诺。

首版必须记录：

- 每千次体验的带宽及运行相关成本。
- 每个审核版本的平均人工耗时、驳回和复审次数。
- 每个有效体验用户的获客成本与支持成本。
- 每个持续活跃作者带来的有效体验及运维负担。

先根据实际成本设定项目预算，再决定免费额度与扩张速度。站内 AI 生成尚未立项，不将未来模型价格下降作为现有商业可行性的保证。

## 19. 主要风险与应对

| 风险 | 可观察信号 | 首轮应对 |
| --- | --- | --- |
| 创作者多，体验者少 | 上传持续增加，圈外用户留存低 | 按类型排查内容质量、兴趣匹配和体验阻力，改善选品；不默认砍掉其他类别 |
| 多类型排序失衡 | 工具被长时游戏挤出首页，或新类别没有探索曝光 | 类型内评估后综合排序，检查探索机会与负反馈，不以固定类别轮播代替推荐 |
| 只有技术演示好看 | 点击高、有效体验和复访低 | 强化玩法/用途描述，以真实体验选品 |
| 重复生成作品淹没首页 | 同质化高、跳出增多 | 提交频控、重复识别、人工审核和探索限额 |
| 发布仍然太麻烦 | 上传检查和预览阶段大量流失 | 给出依赖检查及明确修复说明，提供简单打包指南 |
| 作者只来索取流量 | 发一次即离开，不回复不更新 | 访谈验证价值，优先服务愿意维护作品的作者 |
| 运行或内容风险 | 异常权限、误导、侵权或举报增加 | 隔离、审核、紧急停用与可追溯的版本记录 |
| 头部作品吸走全部曝光 | 新作长期无合格曝光 | 单独的新作探索入口与流量分配复盘 |
| 旧平台推出同类能力 | 作者跨平台发布，回访减少 | 强化作者与用户关系、反馈质量、可迁移性和服务 |
| 运营成本失控 | 审核积压、带宽成本高、低质包激增 | 控制内测规模与额度，先验证单位成本 |
| 无法满足上线要求 | 资质或运营能力评估未完成 | 保持受控测试，缩小能力或延期公开发布 |

## 20. 交付阶段与进入条件

阶段按结果推进。尚未确认团队和预算，本文不承诺固定开发日期。

| 阶段 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：需求确认 | 约 10 位已有作品作者访谈、约 10 位圈外用户体验观察、真实样本包 | 确认主要卡点、作品范围和目标设备；有人愿意提供作品 |
| B：受控 MVP | 综合推荐、可扩展分类、上传、审核、体验、反馈、版本与紧急停用闭环 | 多类作品可在同一首页被发现和体验；核心流程和隔离测试通过 |
| C：邀请内测 | 达到首轮内容与用户样本目标，持续观察至少两个周度批次 | 有成熟留存样本、作者更新与成本数据，能够解释流失 |
| D：公开测试 | 增加供给、完善审核与客服能力、公布规则 | 适用上线要求完成核实，安全和运营能力可承接规模 |
| E：扩展 | 选择站内改编、想法认领或 AI 创作中的一个方向 | 扩展功能有明确用户证据，不同时铺开全部能力 |

建议最小职责包括产品与运营、前端与运行环境、服务端与数据，以及具备明确负责人的安全和上线要求评估；具体人数由团队能力决定。审核是持续工作，不能只在上线前做一次。

## 21. 上线验收场景

以下场景全部完成并保留结果，才可进入邀请内测：

1. 作者上传合法 HTML 与 ZIP，分别完成预览、提审、公开与分享访问。
2. 缺入口文件、外部依赖、超限包及危险压缩路径被正确拒绝，原因可理解。
3. 游客从分享页直接体验；登录后收藏、关注和反馈，不丢失原作品位置。
4. 手机不支持的作品提前提示；支持作品能完成约定核心操作。
5. 作品尝试访问账号、其他作品数据、外网、弹窗和敏感权限时被限制。
6. 评论脚本、恶意元数据与异常消息不会在主站执行或触发越权动作。
7. 加载失败、黑屏、网络中断和普通运行异常可退出与反馈，输入不无故丢失。
8. 作者提交新版本时旧版保持可用；发布和回滚没有混用资源。
9. 反馈与原版本关联，作者修复后用户能看到处理状态。
10. 举报进入队列；紧急停用后首页、分享页、直接资源入口均按要求停止新访问。
11. 核心埋点可串联曝光到体验，作者自访与内部测试单独标识。
12. 作者不能删除正常负面评论；被处理内容具有明确理由和申诉路径。
13. 不选择分类即可在首页看到跨分类推荐；游戏、工具和两类其他创作均可进入同一推荐流，点击对应按钮可真实体验。
14. 主动选择分类后结果匹配；返回综合推荐时恢复原位置，不要求重新选择兴趣。
15. 新增一个类别无需客户端发版，合格作品可完成上传、审核、推荐、搜索与收藏；“其他”类别不被默认排除。
16. 10 秒完成任务的工具不会仅因停留短而被判定低质；跨类报告能分别展示完成、收藏、复用与时长口径。
17. 同作品有多个分类时不重复刷屏；不感兴趣反馈作用范围正确，不能误隐藏全部作品。

## 22. 待确认决策

这是一版基于当前讨论的提案，以下问题不阻止评审，但会影响排期和上线范围：

- 首批作者和真实作品从哪里获得，是否已有可以联系的种子作者？
- 是否接受首版以浏览器为入口，暂缓独立 App？
- 首批应准备哪些游戏、工具及其他创作样本，怎样验证综合推荐对不同用户的发现价值？
- 团队、预算、运营主体与可承担的审核规模是多少？
- 首批用户年龄范围、实际运营方式及对应上线要求如何确定？
- 作品包限制与运行权限能否覆盖目标样本？

已确认的产品方向：**游戏、工具及其他创作共存，首页默认综合推荐，分类辅助发现；不将平台定位为单一游戏社区。**

首版实现提案：**移动浏览器优先、电脑端上传；承接站外创作；通用自包含网页作品容器；无支付、无作品外部联网；公开前审核；P0 完成多类型发现、体验与反馈闭环。** 内容品类可以扩展，技术能力按阶段开放。
