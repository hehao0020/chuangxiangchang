# 🚀 创想场 · IdeaForge

**面向个人创作者的综合作品社区：让作品找到第一批真实用户，并通过反馈持续变好。**

游戏、工具、互动故事、设计和其他创意作品，共存在同一个推荐首页。用户刷到感兴趣的作品，可以直接游玩、使用或探索；作者可以了解作品是否被实际使用、用户遇到什么问题，以及下一版本是否改善了体验。

> **当前状态：产品设计与需求验证阶段。** 本仓库先公开问题定义、产品需求与方案取舍，邀请大家一起验证和完善；目前尚无可运行的平台代码、在线演示或安装包。下列产品能力均为规划。

## 为什么做这个项目

AI 编程与创作工具让更多人开始制作和分享网页游戏、互动故事、轻量工具等可运行作品。我们关注的是作品做出来之后的过程：别人在哪里发现它，怎样真正体验，反馈能否帮助作者继续改进？

这份方案源于一个观察：通过图文或视频看到作品，与亲自使用作品之间，可能仍有寻找入口、适配设备和分散反馈等阻力。第一批重点服务已经做好网页作品、但缺少体验者和具体反馈的个人作者。他们可以创作游戏、工具、故事或设计；先明确服务的人群和任务，同时保持内容类型开放。这些问题的普遍程度需要访谈和实际数据验证。

我们希望跑通：

**创作 → 发布 → 发现 → 直接体验 → 反馈 → 更新。**

作者可以使用任何 AI、可视化工具或传统开发方式；普通用户无需懂代码，也能发现和体验作品。

## 想做成什么样

同一个推荐首页里，可以出现：

| 作品 | 用户动作 |
| --- | --- |
| 一个 3D 射击游戏 | 开始游玩 |
| 一个配色或计算工具 | 立即使用 |
| 一个可旋转的房间设计 | 查看设计 |
| 一个可以选择走向的故事 | 进入故事 |
| 一个物理实验模拟器 | 调参探索 |

统一发现、发布、评论、收藏和关注，保留不同作品各自的体验方式。首页默认综合推荐，分类用于辅助筛选，新类型可以持续加入。

作品同时标注“尝鲜测试 / 持续更新 / 稳定可用”三个体验阶段：想尝新的用户可以参与测试，只想找成熟内容的用户可以减少测试作品。阶段由作者申报并随版本审核，不是平台对品质或安全的保证。

例如，一位作者发布射击游戏，提出“想知道手机操作是否顺手”；平台在内测容量允许时组织目标设备用户体验，反馈关联到当时的版本；作者发布修复后，体验者可自愿回来验证。作品继续在综合首页面向合适的人展示。

## 为什么先公开产品方案

产品设计也可以成为协作的起点。我们希望把需求、假设、取舍和验收条件先写清楚，让大家在投入实现之前就能提出修改、补充案例或参与验证。

当前公开的是一份可持续修订的产品方案。是否值得做、与已有产品是否存在足够差异、用户是否会持续回来，都应接受验证。方案中的冷启动规模、指标阈值和技术限制是提案，不是已经获得的用户、业务数据或实现成果。

## 已有产品与本项目的关系

这类方向已有实践，我们欢迎学习和比较：

- [Websim](https://websim.com/) 已提供游戏与应用的创作入口，以及社区作品的发现和体验。
- [itch.io](https://itch.io/docs/creators/html5) 已支持浏览器直接运行网页作品，官方文档也明确说明可以上传各类 HTML/JavaScript/CSS 项目。
- [vibed](https://vibed.city/landing) 已围绕多类型可交互作品组织信息流，提供站外 HTML 发布、评论及改编等能力。
- [AI 作品集市](https://vibecodingbox.cn/?page=2) 已在中文社区介绍小游戏、小工具、网页的发布、发现和体验；其[教程](https://vibecodingbox.cn/tutorials)也包含站外创作后发布的流程。
- [8x / Paean Remix](https://apps.apple.com/my/app/8x-paean-remix/id6757635048) 的开发者商店说明包含游戏与工具信息流、直接体验、AI 创作发布和改编。

**多类型作品、浏览器体验和创作者社区都不是本项目独有的构想。** 本项目也尚未证明自己比现有产品更好。上述产品是参考，清单并非完整市场调研。

我们进一步把验证重点放在作者发布之后能获得什么：

1. 新作者能否更快获得第一批实际体验者和具体反馈。
2. 用户能否在综合首页找到适合自己的作品阶段和内容，愿意回来继续使用。
3. 反馈能否关联问题、版本与后续验证，帮助作者判断更新有没有改善体验。
4. 游戏、工具等作品能否根据复玩、任务完成、再次使用与运行质量获得合适的推荐。

这些也是其他产品可能已经覆盖的方向，不能直接当作竞争优势。我们需要具体使用经历、对比和数据，来判断剩余问题是什么，以及独立平台是否值得建设。

## 方案中的重点

- **先验证首批用户与反馈。** 第一轮计划邀请约 10 位已有作品的作者，每位选择一个作品，按容量为每个作品邀请约 5 名合适体验者。先看体验与反馈能否带来下一次更新，再评估扩大到 20—30 位作者和约 60 个作品；这些目标尚未达成，也不构成无限免费流量保证。
- **明确运行安全边界。** 提出运行容器隔离、网络和敏感权限限制、版本审核与紧急停用要求；具体实现需要工程验证，不能保证绝对安全。
- **按作品用途评价体验。** 游戏可以观察有效游玩和复玩，工具可以观察任务完成与再次使用；30 秒停留加交互只是其中一种口径，短时完成任务同样可能有价值。异常流量、自刷和真实免费用户分别对待。
- **让反馈关联更新和验证。** 规划作者的本轮体验问题、反馈状态、版本关联与自愿回访，记录“作者已修复”和“用户已验证”的区别；不把更新次数本身当作质量。

## 第一版计划

- 综合推荐首页、可选分类筛选、搜索与关注流。
- 可扩展分类，支持游戏、工具、设计、故事、学习模拟及其他创作。
- 通用网页作品上传、独立分享地址与隔离体验。
- 评论、问题反馈、点赞、收藏和作者关注。
- 作者工作台、版本更新、基础数据与审核管理。
- 作品体验阶段、定向体验问题与受控试玩队列，反馈关联新版本后的复验。

首版运行能力提案为自包含 HTML/网页 ZIP 包。内容类别与技术能力分别管理；外部联网、后端托管、账号支付、站内 AI 创作等能力分阶段评估。

## 怎么验证这条路线

在作者愿意的情况下，记录同一作品在本平台与原有渠道获得有效体验所需时间、有用反馈、回访与再次发布意愿。渠道、人群、作品版本和作者推广投入均需要记录，不能仅凭前后变化就把效果归因于平台。

我们会优先观察新作品在公开 7 天内是否获得至少 5 名独立有效体验者及一条来自体验者的有用反馈，同时看普通用户留存、运行质量和运营成本。详细口径见 PRD；小样本阶段先判断问题，暂不宣称已经形成竞争优势。

## English

IdeaForge (创想场) is a proposed multi-category creation community focused on helping independent creators reach their first real users and improve through version-linked feedback. Games, tools, stories, and design experiments share one recommendation feed, with optional experience-stage filters. This repository contains a product proposal, not a runnable platform. Related products already exist; user evidence and practical comparisons are needed to validate its value.
